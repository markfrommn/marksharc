# DEV-47 User documentation, spec rewrite and legacy closeout

Deliver P2.7 from [MARKSHARC-PLAN.md](MARKSHARC-PLAN.md): the documents users and contributors
need, a specification agents can use, and the closeout of the legacy bug and gap lists.

## Decisions

Settled with the operator before writing:

| Question | Decision |
| --- | --- |
| Depth | Standard: a quickstart, a user guide, real references, an architecture page, a module-authoring guide and per-shell notes. No page per module or per command. |
| Structure | Flat `docs/`. `USERGUIDE.md` and `DEVELOPING.md` are hubs that link to topic pages. Existing topic pages keep their names, so no link breaks. |
| Reader | An outside adopter who has never seen marksharc. Concepts come before commands, and nothing depends on the author's own setup. |
| Specification | The original design is archived. `MARKSHARC-SPEC.md` is rewritten as a current-state contract with a routing table into `docs/`. |
| Module reference | Generated: a summary table, then per-module options, commands, packages, installers and update steps. |
| Extras | A relative-link check, Mermaid diagrams, a troubleshooting section, and a reusable clean-container check. |
| Carried items | Tracked in Linear only. Linear is private, so public pages cite issue keys as plain text and never link to it. |

## Scope

1. **Specification**
   - Copy the design specification to `specs/archive/MARKSHARC-SPEC-2026-11-design.md` with a
     banner and corrected relative links.
   - Rewrite `MARKSHARC-SPEC.md`. Sections 1, 4, 6.1–6.16, 7, 8 and 10 keep their numbers,
     because about sixty code comments cite them. Sections 2, 3, 5, 9, 11 and 12 become pointers
     to the archive. Section 7 points at the generated module reference. The author's private
     module table leaves the live specification.
   - Corrections made against the code: the layout tree, the `core/cli` list, the overlay
     layout (`local/pre.zsh` never existed; `local/post.bash` and `local/post.fish` do), `plugin`
     lines live in `zsh.plugins` and `fish.plugins`, core settings, coexist wiring, and notify in
     Bash as well as zsh.

2. **User pages**
   - `README.md`: a quickstart of about 140 lines.
   - `docs/USERGUIDE.md`, `docs/COMMANDS.md`, `docs/CONFIGURATION.md`, `docs/SHELLS.md`.
   - `docs/MODULES.md`, generated by `tests/support/gen-module-reference`.

3. **Developer pages**
   - `docs/ARCHITECTURE.md`, `docs/MODULE-AUTHORING.md`, `docs/DESIGN-RULES.md`.
   - `docs/DEVELOPING.md` becomes the hub and gains a documentation section.
   - `docs/write-once.md`: Bash applies caller-state directives, including `exit`; the page said
     that was later work.
   - `tests/README.md`: rows for the new tools and checks.

4. **Checks**
   - `tests/support/gen-module-reference` with `--check`.
   - `tests/support/check-doc-links.py`: relative links must name an existing file, and a
     fragment must name a heading.
   - `tests/spec/repo/docs_spec.sh` runs both, with fixtures.
   - `.github/workflows/docs.yml` runs that spec for Markdown and module changes, because the
     main workflow skips Markdown-only changes.
   - `tests/e2e/readme-container.sh` runs the README's own install commands in a clean
     container.

5. **Plan**
   - `MARKSHARC-PLAN.md`: the P2.7 entry matches the issue, three links to files that live in
     `mark-desktop-files` become plain paths, and a mangled forward-plan row is repaired.

## Legacy closeout

`docs/zsh-bugs-and-bogons.md` and `docs/fish-zsh-remaining-gaps.md` in `mark-desktop-files`
recorded defects and gaps in the shell configuration that marksharc replaced. Each item was
checked against the marksharc code and its tests.

Dispositions: **Resolved**, the defect cannot occur in marksharc; **Obsolete**, the code was
removed with no successor; **Accepted**, a deliberate and documented difference; **Carried**,
tracked in a new issue.
